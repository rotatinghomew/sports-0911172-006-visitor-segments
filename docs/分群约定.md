# 行为分群约定

分群能力在现有到访、许可连接与人工名单之上提供可解释的离线分析。分群不自动起业务名、不自动替换人群、不做经营决策；替换名单与发送仍由运营显式执行。分群记录一旦保存不可变，重新分析使用新编号。

## 归因与许可边界

- 设备当前只连接一个主体时，该设备的到访才归因于该主体；之后连接会员号会把该设备历史到访并入，重新分群即反映。
- 共用设备（当前连接多个主体，不论其许可状态）的到访不归因于任何人，计入 `coverage.visits_ambiguous_device`。不能借共同设备把一人的群标签转给另一个人。
- 无分析许可的主体不参与分群，其可归因到访计入 `visits_excluded_no_consent`；缺失许可不是一种兴趣，不构成任何特征或群。
- 未知设备到访计入 `visits_unknown_device`。有许可但可归因到访不足 `min_visits` 的主体保持未入群（`unassigned`），不强行归类。

## 特征

默认特征（`features` 参数可取子集以比较不同特征选择）：

| 特征 | 含义 |
| --- | --- |
| `visits_total` | 可归因到访次数 |
| `active_weeks` | 有到访的不同周数（ISO 周） |
| `distinct_venues` | 到访场馆数 |
| `share_match` / `share_exercise` / `share_mall` / `share_other` | 四类活动到访占比 |
| `spend_per_visit` | 平均每访消费（分） |
| `recency_days` | 距最近到访天数（相对数据内最大到访日） |

## 分群与选择比较

- 算法为 k-means，特征做 z-score 标准化，固定随机种子（默认 117206），同样输入结果可复现。
- `candidates` 对相邻群数给出惯性、轮廓系数、最小群规模与跨周稳定性，用于比较分群选择；不要用单次结果宣称最优。
- 比较特征选择：用不同 `features` 分别 `analyze`，再用 `segments.correspond` 对照成员对应。

## 跨周稳定性与新到访者

- `stability`：用前半周数据训练的分群与全量分群做成员对齐，`agreement` 为一致率；不足两周或样本不足时为 `null`，不得据此宣称稳定。
- `newcomers`：首个可归因周落在后半周的许可主体数量及其中已入群、未入群数。新到访者数据少时保持未入群；解释中的低数据占比提示其归类不确定性。

## 不确定性与警告阈值

每群记录 `uncertainty`（低数据成员数、到质心距离、有消费成员数与消费到访数），并在以下情况给出警告：群规模小于 8（小样本）、仅一次消费记录（偶然购买不能证明稳定偏好）、有消费成员少于 3（偏好证据薄弱）、低数据成员过半。常量见 `product/segments.py`：`LOW_DATA_VISITS=3`、`SMALL_CLUSTER_SIZE=8`、`WEAK_PURCHASE_MEMBERS=3`。

## 群对应（segments.correspond）

比较两次分群，按成员重叠把每个旧群分类：`preserved`（主要成员进入同一新群，阈值 0.6）、`merged`（多个旧群主要进入同一新群，阈值 0.5）、`split`（成员分散到多个新群且无主要去向）、`lost`（仍可归群成员不足一半，对应关系丢失）、`empty`。出现任何非延续分类即在 `alerts` 提醒，不能只沿用旧群号承接业务含义。

## 名单对应（segments.relate）

对照人工名单与分群：名单成员集中于某群达 0.6 视为对应单一分群；分散、部分成员不在分群范围（许可撤回或归因变化）或数据不足时给出告警。人工名单的业务名称不构成学习标签，只用于对照。

## 迁移与一致性（segments.migration / segments.status）

- `migration` 为只读预览：新旧成员的 kept/added/removed、自分群计算后撤回许可而被剔除的 `blocked`、按当前许可过滤的 `proposed_members` 与可触达数、引用该人群的待发消息、以及分群是否已过时。预览不产生任何写入；是否接受含义变化由运营决定，再用 `audiences.replace` 执行。
- `status` 报告自分群计算后的身份连接变化（连接、拆分、撤回）、新到访与已撤回成员，提示重新分群。
- 统计人数、待发名单与实际触达使用一致的合法成员范围：分群统计只含当前许可主体；`audiences.replace` 与 `outreach.queue` 校验许可；`outreach.send` 发送时重验许可，重试不产生重复触达；已发 `delivery` 仅保留 mailing 与 member 凭据。
- `explain` 只含聚合信息，不展示个人到访轨迹；`correspond`、`migration` 只含成员归属，不含行为明细。

## 建议流程

`segments.analyze` → `segments.explain`（差异、覆盖、不确定性）→ 与在用分群 `segments.correspond`、与人工名单 `segments.relate` → `segments.migration` 预览迁移与可触达覆盖 → 运营决定后 `audiences.replace` → `outreach.queue` / `outreach.send`。身份或到访有变化时先 `segments.status`，过时则用新编号重新 `analyze`。
